- [ ] 3. 領域部品: 厳密解、データ生成、誤差指標、適合確認

  - テストは整列方式専用のテストファイルに置く。厳密解のディレクトリには、2方式で共有する補助ファイルや再エクスポート用のファイルを作らない

  - 完了時の状態: 5分布の全要素が有限の正の数であること、正規と多峰で 0 以下が出ないこと、同条件での完全一致と異なるシードでの相違、並び順、不正な件数・パラメータ・シードのエラーの単体テストが通る

## Implementation Notes
- ライセンス判定(1.2): 利用者の判断で許可リストに MPL-2.0(lightningcss)と CC0-1.0(spdx-license-ids)を追加し、CC-BY-3.0 の spdx-exceptions@2.5.0 と spdx-ranges@2.1.1 は --excludePackages で除外した。design.md の許可リストは未更新。
- 乱数(2.1): シード混合は splitmix32 系(加算 0x9e3779b9、finalizer 0x85ebca6b/0xc2b2ae35)を4回適用、先頭20個を読み捨て。nextIntBelow は不正な上限で RangeError を投げる。既知の列はこの選択に依存する。
- 契約(2.4): パラメータ記録の判定関数は `isParamRecord`(src/core/contract/sketch.ts)。後続タスクはこの名前で import する。
- 整列方式(3.1): spec id は `exact-sort-${definition}`(quickselect は `exact-quickselect-…` とする)。投入1回=移動1、容量は初期16で倍増しコピーを移動として数える。併合整列は値同士の比較1回=比較1、書き込み1回=移動1。query は分位点範囲→空の順に検査する。
- quickselect(3.2): 比較は pivot との "x<pivot" 次いで "x>pivot"(同値は2回)、交換=移動2(自己交換は0)、問い合わせごとのコピー=移動n、右側最小値探索は hi>lo かつ上側値を使う定義(linear/midpoint/higher)のみ。pivot 選択は数えない。実測 n=1e5, q=0.5 で比較 約6.3〜6.8n。ExactOptions は両ファイルで別宣言。invalid seed は RangeError。
- データ生成(3.3): 検証順は件数→シード→並び順→分布パラメータ。乱数消費は標本ごと(Box-Muller は u1=nextFloatOpen, u2=nextFloat で cos のみ使用、多峰は山選択に nextFloat 1個)で、並べ替えでは消費しない。変更すると生成値が変わる。
- 誤差指標(3.4): rankError は sortedData の先頭・末尾のみ検証(O(log n) を保つため。整列済みは呼び出し側の前提)。検査順は 分位点→空→estimate→data。順位誤差は |rank-target|/n。
- 適合確認(3.5): runConformance(spec, {seed?}) は13項目(設計の項目に reset 後の再投入比較・同シード同操作数・params JSON を追加)。拒否系は拒否呼び出しの直前直後で操作数・メモリを比較し、回答比較は外側で行う(quickselect は問い合わせで操作数が増えるため)。supportedRange.max が非常に大きい有限値だと max*2 が Infinity になり誤検知しうる。
- ハーネス(4.1): 検証順は data→quantiles→sketches→meta→params。invalid-params の field は meta / params:${spec.id}。空の quantiles は許容(queries が空)。型は harness/types.ts にあり、4.2 は SweepResult/SeriesPoint をここへ追加する。accessor(operationCounts/memoryBytes)が投げた場合は記録されず全体が中断する(許容)。
