- [ ] 2. 手法: GK、KLL、t-digest(互いに独立)
- [x] 2.1 (P) GK を、内部状態の観察を備えた共通規約のアルゴリズムとその生成仕様として実装する
  - ε を検証し、許容範囲(0.0001 以上 0.5 以下)の外や有限でない値は、原因の項目つきの設定の誤りとして返し、作成しない
  - 投入: 不正な値は状態を変えずに拒否する。二分探索で挿入位置を求め(同値は既存の後ろ)、両端なら順位の幅0、それ以外は後続タプルの「g + 順位の幅 − 1」で新しいタプルを作る。探索の比較、タプルのずらし・書き込み・容量拡張の移動(タプルあたり3)を数える
  - 圧縮: 「1 ÷ (2ε)」の切り捨て(最小1)件ごとに、右から左へ、併合の条件(g の和 + 後ろの順位の幅 ≤ 2εn の切り捨て)を満たすタプルを後ろのタプルに併合する。先頭のタプルは併合しない。判定ごとに比較1、書き換えと詰めの移動を数える
  - 問い合わせ: 分位点の範囲 → 空の順に検査する。分位点0は最小値、それ以外は最近順位法の目標順位に対して、最大順位が「目標順位 + εn」を超える最初のタプルの1つ前の値を返し、見つからなければ最大値を返す。調べたタプルごとに比較1
  - メモリ見積もりはタプル数の3倍 + 1 個(値、g、順位の幅、件数)から求める。初期化は ε を保って空に戻す。乱数は使わない。生成仕様の識別子・表示名・パラメータ(手法の種類と ε)を設計どおりに作り、扱える値域は制限しない
  - 内部状態の観察: タプルの一覧(値、g、順位の幅)を値の順に、投入件数と ε とともに複製として返す。状態・操作数を変えず、操作数に数えない
  - 完了時の状態: 小さな入力で、挿入時の順位の幅の規則と圧縮による併合の結果が観察結果のタプルに現れ、観察結果に投入件数と ε が入ること、圧縮でタプル数が投入件数より少なくなること、ε の不正な指定の全区分、分位点0・1が最小値・最大値になること、推定値が投入済みの値のいずれかであること、不正値・範囲外の分位点・空のエラーと状態不変、初期化、同じ入力で同じ結果、生成仕様の識別子とパラメータの単体テストが通る

- [x] 2.2 (P) KLL を、内部状態の観察を備えた共通規約のアルゴリズムとその生成仕様として実装する
  - k(8 以上 65536 以下の整数)とシード(0 以上 2^32 未満の整数、省略時は1)を検証し、不正なら原因の項目つきの設定の誤りとして返す。生成仕様の作成関数に不正なシードが渡されたときは例外を投げる
  - 段ごとの容量を「k × (2/3)^(最上段からの距離)」の切り捨て(下限2)とする。投入は段0の末尾に書き(移動1)、保持要素数の合計が容量の合計を超えたら、容量以上の最も下の段を compaction する。最上段なら先に段を足す
  - compaction: 段を計数付き整列で並べ、要素数が奇数なら最小の要素を残し、残りの偶数個から共通基盤の乱数で選んだ偶数番目か奇数番目を上の段に送り、残りを捨てる。書き込みを移動として数え、compaction の回数を記録する
  - 問い合わせ: 分位点の範囲 → 空の順に検査し、全段の要素を重み(2の段数乗)つきで作業領域に集め(要素ごとに移動2)、計数付き整列で並べ、重みの累計が初めて最近順位法の目標順位以上になる要素の値を返す。調べた要素ごとに比較1。状態は変えない
  - メモリ見積もりは保持要素数 + 段数 + 1 個から求める。初期化は段・件数・compaction の回数・操作数を戻し、乱数を同じシードで作り直す。生成仕様の識別子・表示名・パラメータ(手法の種類、k、縮小率)を設計どおりに作り、扱える値域は制限しない
  - 内部状態の観察: 段ごとに、段の番号、重み、容量、保持している値の一覧(保持順)を、投入件数、k、compaction の回数とともに複製として返す。状態・操作数・乱数列を変えず、操作数に数えない
  - 完了時の状態: 観察結果で段の重みと要素数の積の合計が投入件数に等しいこと、容量の計算と段の追加、compaction で奇数のとき最小の要素が残ること、k とシードの不正な指定、重みの累計による推定、同じシードで同じ結果・違うシードで異なる結果になりうること、不正値・範囲外の分位点・空のエラーと状態不変、初期化で乱数列も戻ること、生成仕様の識別子とパラメータの単体テストが通る
  - _Depends: 1.1_
  - _Boundary: Kll_
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5, 2.6, 2.7, 2.8, 4.1, 4.3, 4.4, 4.5, 4.6, 4.7, 4.8, 5.2, 6.1, 6.2, 6.3_

- [x] 2.3 (P) t-digest を、内部状態の観察を備えた共通規約のアルゴリズムとその生成仕様として実装する
  - 圧縮パラメータ(10 以上 10000 以下)とスケール関数(k0、k1、k2)を検証し、不正なら原因の項目つきの設定の誤りとして返す
  - 投入: 不正な値は状態を変えずに拒否する。値をバッファ(容量は圧縮パラメータの5倍の切り上げ)の末尾に書き、最小値・最大値を更新し、バッファが満杯になったらまとめる
  - まとめ: バッファを計数付き整列で並べ、既存の centroid と値の順に1列として読み、スケール関数の上限を超えない範囲で貪欲に centroid にまとめる(各 centroid には少なくとも1項目)。まとめる向きは常に昇順。先頭同士の比較と、上限に収まるかの判定を比較として、centroid の書き出しを移動として数える
  - 問い合わせ: 分位点の範囲 → 空の順に検査し、バッファが残っていれば先にまとめる(その費用は問い合わせの操作数に含める)。点(0, 最小値)、各 centroid(重みの中心の位置, 平均値)、(投入件数, 最大値)を結ぶ折れ線で目標位置「分位点 × 投入件数」の値を補間し、最小値以上・最大値以下に収めて返す。調べた点ごとに比較1
  - メモリ見積もりは centroid 数の2倍 + バッファ件数 + 3 個から求める。初期化はパラメータを保って空に戻す。乱数は使わない。生成仕様の識別子・表示名・パラメータ(手法の種類、圧縮パラメータ、スケール関数、バッファ容量)を設計どおりに作り、扱える値域は制限しない
  - 内部状態の観察: centroid の一覧(平均値と重み)を値の順に、まだまとめていない値の件数、最小値・最大値(空なら null)、投入件数、圧縮パラメータ、スケール関数とともに複製として返す。バッファはまとめず、状態・操作数を変えない
  - 完了時の状態: バッファが残った状態で観察しても centroid とバッファ件数が変わらないこと、圧縮パラメータとスケール関数の不正な指定、バッファ満杯と問い合わせでのまとめ、重みの合計 + バッファ件数 = 投入件数、分位点0・1が最小値・最大値、重み1の centroid だけなら推定値が実データになること、2点間の線形補間の数値例、k0 と k1 で裾の centroid の重みが異なること、不正値・範囲外の分位点・空のエラーと状態不変(拒否された問い合わせではまとめないこと)、初期化、同じ入力で同じ結果の単体テストが通る
  - _Depends: 1.1, 1.2_
  - _Boundary: TDigest_

## Implementation Notes

- 実装ファイルは `src/streaming/` に置く(`errors` / `sort` / `scale` / `gk` など)。共通基盤は `../core` の入口だけから取り込む。
- 整列は結果が作業領域に残ったとき、書き戻しの移動(長さ × 1 または 2)も数える(1.1)。
- GK は `sort` と `scale` を取り込まない(設計どおり)。タプル列の初期容量は 16 で、満杯のたびに倍にする(複製したタプルごとに移動 3)(2.1)。
- 等価変異: GK の併合閾値の `Math.floor` と、圧縮周期の `Math.max(1, …)` は、整数比較・ε ≤ 0.5 の制約により外してもテストでは区別できない。テストの強化では floor と ceil の違いを検出すれば足りる(2.1)。
- レビューは「仕様の規則を1つずつ壊しても落ちるテストがあるか」を確かめる。重複値の挿入位置、周期・閾値の端数、問い合わせの厳密比較は、端数や等号の境界の数値例で固定する。
- KLL の段の容量は設計の式を浮動小数で素直に計算する。`81·(2/3)^3` は 23.999999999999993 となり切り捨てで 23 になる(正確な値は 24)。文書の数値例(5.2)ではこうした k を避けるか、この値を明示して固定する(2.2)。
- KLL は段ごとの配列の拡張を移動に数えない(設計は要素の書き込みだけを数える)。GK は容量拡張の移動を数える点が異なる(2.2)。
- 2.2 のレビューで残った小さな穴: 容量の境界が浮動小数で変わる k の固定と、圧縮を起こさない投入(件数 50 など)で乱数を引かないことの固定。4.3 または 5.2 のテストで補える(2.2)。
- t-digest の操作数の数え方(設計の文言が曖昧な点を、次のとおり読んで固定した)。後続の 4.3(費用のテスト)と 5.x(文書)も同じ読みに従う(2.3)。
  - 投入: 比較 2(最小値・最大値との比較)、バッファへの書き込みで移動 1、最小値・最大値を更新したら更新した境界ごとに移動 1。最初の投入は比較 2・移動 3。
  - 問い合わせ: 始点 (0, 最小値) は調べた点に数えない。調べる点は最初の centroid から始め、位置が目標以上の最初の点で終わる。
  - 目標の位置がある点の位置とちょうど等しいときは、補間せずにその点の値を返す(補間の丸め誤差で最大値に届かないのを避ける)。
- 実験の誤りの `field` は、ケースの識別(`cases[i].label`)と手法の指定(`sketches[i].<項目>`)にだけ一覧内の位置を含め、一覧そのものの誤りは `orders`・`trialSeeds`・`sketches` とする。識別子の重複は `invalid-experiment` の `sketches`。`orders` と `trialSeeds` は `undefined` のときだけ既定値(`['random']`、`[データのシード]`)を使い、`null` は誤りとする(3.2)。
- `src/streaming/experiment.test.ts` は、このリポジトリで唯一 `vi.mock` を使う(生成仕様を1回だけ作る・データ生成を組ごとに1回・ハーネス呼び出しを組ごとに1回という、呼び出し回数の要求を確かめるため)。呼び出しは本物に通すスパイで、呼び出し回数と順序だけに依存する(3.2)。
- 依存方向のテスト(`public-api.test.ts`)は、段(errors→sort→scale→3手法→config→experiment→index)を全順序にして「兄弟は小さい段だけ取り込む」と、タスクが挙げる禁止(GK は sort・scale を、KLL は scale を取り込まない・3手法は互いを取り込まない・外部は `'../core'` の入口だけ)を強制する。設計の図にない辺(`scale→sort`、`config→sort`、`experiment→手法`)は許すので、より厳しくするなら、ファイルごとの許可リストに替える(4.1)。
