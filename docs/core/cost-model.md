# 操作数とメモリ見積もりの数え方

アルゴリズムの計算効率は、操作数とメモリ見積もりの2つの指標で比べる。どちらも、全アルゴリズムが同じ規則で数える。実装は`src/core/cost/op-counter.ts`と`src/core/cost/memory-model.ts`にあり、`OperationCounter`、`BYTES_PER_NUMBER`、`estimateBytes`として公開している。

## 操作数の種別

操作数は比較と移動の2種類で、各アルゴリズムが`operationCounts()`で累計を返す。累計には値の投入と分位点の問い合わせの両方が含まれ、`reset()`で0に戻る。

比較は、値と値の大小比較を1回行うごとに1と数える。区切り値(pivot)との比較も値同士の比較として数える。移動は、数値またはカウンタを記憶領域の1要素へ書き込むごとに1と数える。2つの要素を入れ替えると2回書き込むので、交換は2と数える。四則演算、添字の計算、ループの制御、引数の検査、乱数の生成は数えない。

2つの厳密解は、どちらも実際に実行した比較と書き込みだけを数える。実行しなかった処理は数えない。

## 整列方式の厳密解

整列方式(`createSortExact`)は、値を投入順に配列へ保持し、問い合わせの時点で整列済みでなければボトムアップの併合整列を行う。

投入は1回あたり移動1回と数える。配列の容量は初期値が16で、いっぱいになると2倍に拡張する。拡張時には保持している件数と同じ回数の移動を数える。17個目を投入すると、拡張のコピー16回と投入1回で移動が17回増える。17個を続けて投入したときの移動は、投入17回と拡張16回で合計33回になる。

問い合わせでは、前回の整列以降に投入があったときだけ併合整列を行う。整列済みなら、整列の操作数は増えない。投入があれば、次の問い合わせで全体を整列し直す。併合整列は幅1の列から始め、幅を2倍にしながら隣り合う2つの列を併合する。併合のたびに、左の列の先頭と右の列の先頭を比べて比較を1回数え、小さい方を出力側の配列へ書き込んで移動を1回数える。どちらかの列が尽きたあと、残りの列を出力側へ書き込むときは比較をせず、書き込みごとに移動を1回数える。同値のときは左の列を先に出すので、整列は安定である。各段で全要素を1回ずつ書き込むため、移動は段の数だけ件数n回ずつ数えられ、段の数はceil(log2(n))である。

整列が終わったあとの順位の計算(`resolvePosition`)と、2つの値からの補間は、四則演算なので数えない。

### 例 逆順に並んだ8個のデータ

[8, 7, 6, 5, 4, 3, 2, 1]を順に投入すると、投入で移動が8回数えられ、比較は0回である。続けてq = 0.5で問い合わせると、併合整列が走る。幅1の段では4回の併合で比較が4回、幅2の段では2回の併合で比較が4回、幅4の段では1回の併合で比較が4回で、比較は合計12回になる。移動は3段で8回ずつなので24回である。累計は比較12回、移動32回(投入の8回と整列の24回)になる。同じ状態でもう一度問い合わせても、整列済みなので累計は変わらない。

## quickselect方式の厳密解

quickselect方式(`createQuickselectExact`)は、値を投入順に保持し、問い合わせのたびに配列のコピーを作って、そのコピー上で選択を行う。整列方式と違い、元の配列は並べ替えず、問い合わせの結果も保持しないので、問い合わせのたびにコピーと選択の費用がかかる。

投入と容量の拡張は整列方式と同じで、投入は移動1回、拡張は保持件数と同じ回数の移動を数える。問い合わせでは、まずコピーの作成でn回の移動を数える。そのあと反復型の3分割quickselectで、目的の順位(0始まりでlo番目)の値を選ぶ。

3分割では、区切り値を1つ選び、範囲内の各要素を区切り値と比べて、小さい値、等しい値、大きい値の3つの領域に分ける。各要素について、まず「区切り値より小さいか」を比べて比較を1回数える。小さければ、小さい領域の末尾との入れ替えを行う。小さくなければ、続けて「区切り値より大きいか」を比べて比較をもう1回数える。大きければ、大きい領域の先頭側との入れ替えを行う。どちらでもなければ等しい値で、入れ替えはしない。つまり、小さい値の比較は1回、大きい値と等しい値の比較は2回になる。入れ替えは移動2回と数えるが、入れ替える相手が自分自身の位置のときは入れ替えを実行しないので移動は0回である。目的の順位が等しい値の領域に入ったところで選択は終わり、そうでなければ該当する側へ範囲を狭めて繰り返す。

区切り値は乱数で選ぶ。乱数の生成は数えない。シードを指定でき、同じシードと同じ入力なら同じ操作数になる。`reset()`はシードから乱数を作り直す。

分位点の定義がlinear、midpoint、higherのときは、位置のhiがloより大きければ、上側の値も必要になる。選択が終わった時点で、lo番目より右の要素はすべてlo番目以上なので、lo + 1番目の値は右側の最小値である。最初の候補は比較せずに採用し、残りの要素を1つずつ現在の最小値と比べて、比較を1回ずつ数える。lowerとnearest-rankは上側の値を使わないので、この探索をしない。位置のhiとloが等しいときも探索しない。

### 例 すべて同じ値のデータ

[5, 5, 5, 5]を投入し、q = 0.5で問い合わせる。シードは結果に影響しない。投入で移動が4回数えられ、比較は0回である。問い合わせではコピーで移動が4回増える。位置はh = 1.5なので、lo = 1、hi = 2になる。3分割では4個のすべてが等しい値で、各要素の比較が2回ずつ、合計8回になる。入れ替えはなく、1回の分割で目的の順位が等しい値の領域に入るので選択が終わる。

定義がlinearのときは、上側の値を探す。添字2の要素を候補に採用し、添字3の要素と比べるので、比較が1回増える。累計は比較9回、移動8回になる。定義がlowerのときは探索がないので、累計は比較8回、移動8回になる。

### 整列方式との違い

整列方式は、整列の費用を一度払えば、次の投入まで何度でも追加の費用なしで問い合わせができる。quickselect方式は、問い合わせのたびにコピーと選択の費用を払う。件数が十分大きく、投入のあとに問い合わせを1回だけ行うなら、整列よりquickselectの方が操作数は少なくなる。投入せずに問い合わせを繰り返すなら、整列方式の方が少なくなる。

## メモリ見積もり

メモリ見積もりは(保持している数値の個数 + 保持しているカウンタの個数) × 8バイトで、`estimateBytes({ numbers, counters })`が計算する。1個あたりのバイト数は`BYTES_PER_NUMBER`で、値は8である。倍精度浮動小数点数1個の大きさに合わせている。

見積もりは、取得した時点で保持している状態だけから計算する。2つの厳密解は、保持している値の個数をnumbersに、カウンタの個数を0として渡す。投入した値が10個なら80バイト、17個なら136バイトである。10個の数値と3個のカウンタを保持するアルゴリズムなら、(10 + 3) × 8 = 104バイトになる。

次のものは、見積もりに含めない。配列の余白(17個を投入したときの容量32のうち、使っていない15個分)、オブジェクトの管理領域、併合整列が作る作業用の配列、quickselectが問い合わせごとに作るコピー、乱数生成器の状態、操作数の計数器である。問い合わせの途中で一時的に使う領域は、問い合わせが終わると見積もりには現れない。比べたいのは、アルゴリズムが答えを出すために持ち続ける状態の大きさだからである。

## 実測の処理時間や実メモリ使用量とは別の指標

操作数とメモリ見積もりは、アルゴリズムの論理的な動作を数えた値であり、実際に計った処理時間や実メモリ使用量とは別の指標である。同じ入力と同じシードなら、実行する環境にかかわらず同じ値になる。

実際の処理時間は、JavaScriptの実行系、CPUのキャッシュ、メモリの割り当て、ガベージコレクションに左右される。比較1回と移動1回の実際の時間も同じではない。計測ハーネスは処理時間を`elapsedMs`として別に記録しており、操作数から処理時間を推定してはいけない。

実メモリ使用量も、前節に挙げた除外分のほか、実行系が確保する領域を含むので、見積もりより大きくなる。見積もりが小さいアルゴリズムが、実際のプロセスのメモリ使用量でも小さいとは限らない。2つの指標は、アルゴリズムどうしを同じ定義で比べるための物差しとして使い、実機の性能の予測には使わない。
