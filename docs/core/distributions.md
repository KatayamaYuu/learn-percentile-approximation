# データ分布

テストデータは`generate({ distribution, count, seed, order })`で作る。実装は`src/core/data/generate.ts`と`src/core/data/distributions.ts`にある。分布、件数、シード、並び順が同じなら、毎回まったく同じ数値列を返す。返す値はすべて有限の正の数で、Float64Arrayに入る。分布は5種類あり、どれも後述の理由で正の値に限っている。

## 5つの分布

| kind | パラメータ | 形状 |
| --- | --- | --- |
| uniform | min, max | 区間[min, max)で平らな分布 |
| normal | mean, stdDev | 平均meanを中心に左右対称の釣り鐘型で、0以下を除いた分布 |
| lognormal | mu, sigma | 右に長く裾を引く単峰の分布 |
| heavy-tail | scale, shape | scale以上で、べき乗則に従って裾が非常に長い分布 |
| multimodal | modes | 正規分布を重みつきで混ぜた、山が2つ以上ある分布 |

uniformは、minとmaxがどちらも0より大きい有限の数で、maxがminより大きい必要がある。値はminを含み、maxを含まない。最も素直な分布で、順位と値の関係がほぼ直線になる。

normalは、meanとstdDevがどちらも0より大きい有限の数である必要がある。標準正規乱数をBox-Muller法で作り、mean + stdDev × 標準正規乱数を標本とする。標本が0以下になったときは捨てて引き直す。

lognormalは、muが有限の数で、sigmaが0より大きい有限の数である必要がある。標本はexp(mu + sigma × 標準正規乱数)で、常に正になる。中央値はexp(mu)、平均はexp(mu + sigma² / 2)なので、sigmaが大きいほど平均が中央値より大きく右にずれる。

heavy-tailはパレート分布である。scaleとshapeがどちらも0より大きい有限の数である必要がある。標本はscale / U^(1/shape)で、Uは(0, 1]の一様乱数とする。最小値はscaleで、値x以上になる確率は(scale / x)^shapeになる。shapeが小さいほど裾が重く、shapeが1以下だと理論上の平均が有限にならず、2以下だと分散が有限にならない。

multimodalのmodesは、weight、mean、stdDevを持つ山の配列で、2個以上が必要である。各山のweight、mean、stdDevはどれも0より大きい有限の数で、重みの合計も有限でなければならない。重みは合計が1になるよう正規化して使う。1標本ごとに、重みに比例した確率で山を1つ選び、その山のmeanとstdDevでnormalと同じ方法で標本を作る。

パラメータが条件を満たさないとき、generateはinvalid-parameterのエラーを返し、どのフィールドがなぜ不正かを示す。件数は1以上1千万以下の整数でなければならず、そうでなければinvalid-countを返す。シードは0以上2の32乗未満の整数でなければならず、そうでなければinvalid-seedを返す。検証は件数、シード、並び順、分布パラメータの順に行う。パラメータが条件を満たしていても、オーバーフローやアンダーフローで標本が有限の正の数にならなかったときは、部分的な列を返さずnon-finite-sampleのエラーを返す。たとえばlognormalでmuが-1000のとき、exp(mu)が0になるのでこのエラーになる。

## 0以下の値の棄却

normalとmultimodalは、数学的には0以下の値も取りうる。このリポジトリでは、パーセンタイルの対象を正の数に限っているため、0以下の標本を採用せずに引き直す。その結果、返す分布は元の正規分布から0以下の部分を切り落とし、残りを正規化した打ち切り正規分布になる。multimodalでは山を選んだあとで、選んだ山の中で引き直す。山の選択確率は重みのとおりに保たれ、各山だけが打ち切られる。

meanがstdDevに比べて十分に大きければ、0以下になる確率は無視できるので、打ち切りの影響はほとんどない。meanが小さくなるにつれて影響は大きくなる。標本が正になる確率はmean / stdDevが1のとき約0.84、0.5のとき約0.69で、meanが0に近づくと0.5に近づく。引き直しのたびに乱数を消費するため、生成にかかる乱数の個数も増える。同じシードなら引き直しを含めて同じ結果になる。

打ち切りによって、標本の平均はパラメータのmeanより大きくなり、標準偏差はstdDevより小さくなる。たとえばmean = 1、stdDev = 1のとき、標本の平均は約1.29になる。パラメータのmeanとstdDevを、生成した分布の平均と標準偏差として読んではいけない。生成した値の分布を知りたいときは、meanをstdDevの3倍以上にして打ち切りを避けるか、生成した列から直接計算する。

## 乱数の消費と並び順

生成は標本ごとに乱数を順に消費する。uniformとheavy-tailは1標本あたり乱数を1個使う。normalとlognormalはBox-Muller法の1回分として2個を使い、normalは棄却するたびにこの2個を使い直す。multimodalは山の選択に1個を使い、そのあとの標本生成はnormalと同じである。この消費順序を変えると、同じシードでも生成される値が変わる。

orderにはrandom、ascending、descendingを指定でき、省略するとrandomになる。ascendingとdescendingは、randomで生成した列を整列し直したものである。並べ替えでは乱数を使わないので、3つの並び順は同じ値の集まりを別の順に並べた列になる。アルゴリズムが投入順に影響されるかどうかは、同じ値を3つの並びで投入して比べると確かめられる。

## 近似アルゴリズムの誤差への影響

近似アルゴリズムの誤差は、分布の形によって変わりやすい。ここでは影響が出うる方向だけを述べる。実際の大きさはアルゴリズムと条件ごとに計測して確かめる。

uniformは密度が一定で、順位と値がほぼ比例する。分布の形に起因する誤差が出にくいので、アルゴリズム本来の誤差を見るための基準に使える。

normalは中心に値が集まるため、中央付近では近い値が密に並び、値の誤差は小さくても順位の誤差は大きくなりうる。端の分位点では値がまばらになり、逆の傾向が出る。

lognormalは右に歪んでおり、高い分位点で値の間隔が急に広がる。値を等間隔に区切る方式は、高い分位点で相対誤差が大きくなりやすい。

heavy-tailは、まれに極端に大きな値が出る。p99やp99.9のような高い分位点では、隣り合う順位の値の差が非常に大きいので、順位のわずかなずれが値の大きな誤差になる。値の範囲を固定して区切る方式は、最大値が事前に分からないと扱いにくい。

multimodalは、山と山の間にほとんど値がない領域を作る。分位点がその谷にまたがると、近隣の順位で値が大きく飛ぶので、補間する方式は谷の中の値を返して誤差が大きくなりうる。
