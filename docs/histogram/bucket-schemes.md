# バケット境界の決め方

固定バケットのヒストグラムは、値の範囲をあらかじめバケットに区切り、各バケットに入った値の件数だけを持つ。区切り方(境界列)で誤差の出方が変わる。実装は`src/histogram/boundaries.ts`にあり、`buildBoundaries`として公開している。境界の個数は「バケット数 + 1」で、先頭が全体の下限、末尾が全体の上限である。

## 3種類の境界

等幅は、下限から上限までを同じ幅のバケットに分ける。下限10、上限50、バケット数4なら、境界は10、20、30、40、50になる。

指数幅は、隣り合う境界の比が一定になるように分ける。下限1、上限1024、バケット数10なら、境界は1、2、4、8、…、1024で、比は常に2である。値の桁が大きく変わる分布(対数正規分布や重い裾の分布)では、小さい値の側のバケットが細かくなる。ただし、境界列は固定であり、相対誤差の上限は保証しない。相対誤差を保証する手法は、別のspec(relative-error-sketches)の対象である。

任意境界は、昇順の境界列をそのまま使う。隣り合う境界の間が1つのバケットになる。

## 区間の包含

バケットは、下側の境界を含み、上側の境界を含まない区間である。最後のバケットだけは上側の境界も含む。

下限10、上限50、バケット数4の等幅では、バケットは[10, 20)、[20, 30)、[30, 40)、[40, 50]になる。値20は[20, 30)に入る。全体の上限である値50は、最後のバケット[40, 50]に入る。

## 範囲外の値

全体の下限未満、または全体の上限より大きい値は、端のバケットに寄せずに拒否する(`unsupported-value`)。拒否された値は件数にも操作数にも反映されない。端に寄せると、端のバケットの誤差の理由が説明できなくなるためである。

実験では、範囲を固定で与えるか、生成したデータの最小値と最大値(`'data-extent'`)から決める。固定の範囲がデータを覆わないときは、ヒストグラムの結果にだけ投入段階のエラーが記録され、厳密解の結果は残る。

## 不正な指定

次の指定はエラーになり、ヒストグラムは作られない。

- 下限または上限が、有限の正の数でない
- 下限が上限以上である
- バケット数が、1以上10万以下の整数でない
- 任意境界が2個未満、または狭義単調増加でない
- 丸めの結果、隣り合う境界が等しくなる(例: 下限1、上限1 + 2.2e-16で4バケット)

## 操作数とメモリ

投入1回の操作数は、共通基盤の数え方(`docs/core/cost-model.md`)に従う。

- 移動は2回である。バケットの件数と総件数を1つずつ増やす。
- 比較は、等幅と指数幅では最大3回、任意境界では二分探索の`ceil(log2 バケット数)`回以下である。等幅と指数幅は、計算で求めたバケットの添字を境界の配列と比べて補正する。計算の誤差は1バケット以内なので、補正の比較は最大3回で済む。

メモリ見積もりは、境界(バケット数 + 1個)と、カウンタ(バケット数 + 1個。バケットごとの件数と総件数)の合計に8バイトを掛けた`(2 × バケット数 + 2) × 8`バイトである。投入した件数に依存しない。
