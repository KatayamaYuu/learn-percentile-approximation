# GK(Greenwald-Khanna): 順位誤差を決定的に保証する要約

GKは、値の列を少数のタプルに要約し、どの分位点でも順位誤差がε以下の値を返す手法である。乱数は使わず、同じ入力からは必ず同じ結果になる。実装は`src/streaming/gk.ts`にある。この文書の数値例は、`src/streaming/docs-examples.test.ts`が実装の出力と照らして確かめている。

## タプルと順位の幅

要約は、値の昇順に並んだタプル(v, g, Δ)の列である。n は投入した件数、ε は許容する順位誤差(件数に対する割合)である。

- v: 投入された値の1つ。
- g: 直前のタプルの最小順位との差。つまり、このタプルが「受け持つ」件数である。
- Δ: 順位の幅。このタプルの値の真の順位が取りうる範囲の広さを表す。

先頭からi番目までのgを足したものを最小順位 rmin_i、それにΔ_iを足したものを最大順位 rmax_i と呼ぶ。

- rmin_i = g_0 + g_1 + … + g_i
- rmax_i = rmin_i + Δ_i

タプルiの値の真の順位(整列したデータでの位置、1始まり)は、rmin_i 以上 rmax_i 以下にある。タプルが元の値をすべて覚えているわけではないので、順位は範囲でしか分からない。Δが大きいほど、順位があいまいになる。

## 不変条件

実装は、次の3つを常に保つ。

1. gの合計は件数nに等しい(Σ g = n)。
2. すべてのタプルで g + Δ ≤ max(1, ⌊2εn⌋)。
3. 先頭のタプル(最小値)と末尾のタプル(最大値)は Δ = 0。

条件2が、このあとの誤差の議論の中心である。右辺の上限を L = max(1, ⌊2εn⌋) と書く。nが増えてもLは減らない(⌊2εn⌋は同じ値が続くことがある)ので、いったん満たした条件は、投入だけでは崩れない。

## 挿入

値 v を投入するときは、次の順に処理する。

1. v より大きい最初のタプルを二分探索で探す(同じ値は既存のタプルの後ろに入る)。そのタプルを「後続」と呼ぶ。
2. 新しいタプルは g = 1 で、Δ は次のとおり。
   - 新しい最小値(後続が先頭)か、新しい最大値(後続がない)なら Δ = 0。
   - それ以外は Δ = 後続の g + 後続の Δ − 1。
3. タプルを後ろにずらして新しいタプルを挿入し、nを1増やす。
4. nが圧縮の周期 max(1, ⌊1/(2ε)⌋) の倍数になったら、圧縮する。

Δの式は、順位の幅から理由が分かる。直前のタプルの最小順位を P、投入前の後続の最大順位を R(= P + 後続のg + 後続のΔ)とする。新しい値は直前の値のあとにあるので、真の順位は P + 1 以上である。また新しい値は後続の値より前にあるので、投入後の真の順位は、投入前の後続の真の順位以下で、R 以下である。したがって順位の幅は Δ = R − (P + 1) = 後続のg + 後続のΔ − 1 になる。新しい値より後ろのタプルは、最小順位も最大順位も1ずつ増えるが、gもΔも変わらない。

この式は、新しいタプルの g + Δ が後続の g + Δ と等しいことを意味する。後続は不変条件を満たしていたので、新しいタプルも満たす。最小値・最大値では Δ = 0 を使うため、g + Δ = 1 である。論文の挿入は Δ を ⌊2εn⌋ とするが、この実装は後続から求めるので Δ が小さくなる。

## 圧縮

圧縮は、タプルの数を減らす操作である。閾値を T = ⌊2εn⌋ とする。末尾の1つ手前のタプルから、先頭の次のタプルまで(先頭は対象にしない)、右から左へタプルiについて次を調べる。

- g_i + g_{i+1} + Δ_{i+1} ≤ T なら、タプルiを捨てて、その g をタプルi+1に足す(g_{i+1} ← g_{i+1} + g_i)。

併合後のタプルは(v_{i+1}, g_i + g_{i+1}, Δ_{i+1})で、最小順位も最大順位も、併合前のタプルi+1と同じである。後ろのタプルの順位の範囲は変わらず、タプルiの値は要約から消える。併合後の g + Δ が T 以下であることを判定の式が確かめているので、条件2は保たれる。

先頭は併合しないので、最小値は残る。末尾は併合の相手(i+1)にしかならないので、最大値も残る。

論文は、Δの大きさでタプルを階層(バンド)に分け、バンドが近いタプルだけを併合して、要約の大きさの上限 O((1/ε) log(εn)) を証明する。この実装はバンドを計算せず、周期ごとに右から左へ上の判定を適用するだけである。順位誤差の保証は条件2だけで決まるので変わらないが、タプルの数の上限は証明されていない。実測の大きさは`experiments.md`で見る。

## 問い合わせ

分位点 q の目標順位を r = ceil(n × q)(共通基盤の最近順位法と同じ規則)、許容幅を e = ε × n とする。

- q = 0 なら、先頭のタプルの値(最小値)を返す。
- それ以外は、先頭から rmax_i を求めていき、rmax_i が r + e を初めて超えるタプルiを探して、1つ前のタプルi−1の値を返す。超えるタプルがなければ、末尾のタプルの値(最大値)を返す。

## 順位誤差がε以下になる理由

返された値の真の順位と、目標順位 r の差が e = εn 以下であることを示す。まず ⌊2εn⌋ < 1 の間は、圧縮が何も併合しない(g + g + Δ が2以上になる)ので、すべてのタプルが g = 1、Δ = 0 のままである。要約は全件を持つので、誤差は0である。以降は ⌊2εn⌋ ≥ 1 とし、L = ⌊2εn⌋ ≤ 2εn を使う。

**探索で止まったとき**(rmax_i > r + e となる最初のタプルiがある場合):

1. 先頭は rmax_0 = 1 ≤ r + e なので、止まるタプルiは1以上であり、i−1が存在する。
2. iが最初なので、rmax_{i−1} ≤ r + e。返す値 v_{i−1} の真の順位は rmax_{i−1} 以下なので、真の順位 ≤ r + e。
3. rmin_{i−1} = rmin_i − g_i である。rmax_i = rmin_i + Δ_i なので、rmin_{i−1} = rmax_i − Δ_i − g_i。条件2より g_i + Δ_i ≤ L ≤ 2εn なので、rmin_{i−1} ≥ rmax_i − 2εn。rmax_i > r + e だったので、rmin_{i−1} > r + e − 2εn = r − e。v_{i−1} の真の順位は rmin_{i−1} 以上なので、真の順位 > r − e。

2と3から、真の順位は r − e と r + e の間にあり、目標順位との差は e = εn 以下である。順位誤差(差を件数nで割った値)はε以下になる。

**止まらなかったとき**(末尾の値を返す場合): 末尾は Δ = 0 で rmax = n なので、n ≤ r + e である。一方、r ≤ n なので、末尾の値(最大値)の順位nと目標順位rの差は、n − r ≤ e である。

**q = 0 のとき**: 最小値の順位は1で、目標順位 r も1である。

値に重複があるとき、共通基盤の順位誤差は、重複した値の順位のうち目標順位に最も近いものを使うので、上の議論の順位の範囲に収まる限り、誤差は上の上限より大きくならない。

この導出が使うのは、条件2(g + Δ ≤ 2εn)と、rmin・rmaxが真の順位の範囲であること(挿入と併合がそれを保つ)の2点だけである。圧縮のやり方(バンドの有無)には依らないため、バンドを使わない簡略化でも保証は変わらない。

## 例 ε = 0.2、値 5、3、8、1、9、2、7、4、10、6

ε = 0.2 なので、圧縮の周期は max(1, ⌊1/0.4⌋) = 2 件ごとである。閾値は T = ⌊0.4n⌋ で、n = 2、4、6、8、10 のとき、それぞれ 0、1、2、3、4 になる。次の表は、1件投入するごとの`inspect()`の結果(タプルは(値, g, Δ))である。

| n | 投入した値 | 圧縮の閾値T | タプル |
|---|---|---|---|
| 1 | 5 | — | (5,1,0) |
| 2 | 3 | 0 | (3,1,0) (5,1,0) |
| 3 | 8 | — | (3,1,0) (5,1,0) (8,1,0) |
| 4 | 1 | 1 | (1,1,0) (3,1,0) (5,1,0) (8,1,0) |
| 5 | 9 | — | (1,1,0) (3,1,0) (5,1,0) (8,1,0) (9,1,0) |
| 6 | 2 | 2 | (1,1,0) (2,1,0) (5,2,0) (9,2,0) |
| 7 | 7 | — | (1,1,0) (2,1,0) (5,2,0) (7,1,1) (9,2,0) |
| 8 | 4 | 3 | (1,1,0) (2,1,0) (5,3,0) (9,3,0) |
| 9 | 10 | — | (1,1,0) (2,1,0) (5,3,0) (9,3,0) (10,1,0) |
| 10 | 6 | 4 | (1,1,0) (5,4,0) (6,1,2) (10,4,0) |

n = 6 の圧縮(T = 2)を手で追う。圧縮の前は、値1、2、3、5、8、9がすべて g = 1、Δ = 0 である(2は、後続の5が Δ = 0、g = 1 なので Δ = 1 + 0 − 1 = 0)。右から調べる。

1. 8を調べる: g(8) + g(9) + Δ(9) = 1 + 1 + 0 = 2 ≤ 2。8を捨てて9に併合し、(9,2,0)になる。
2. 5を調べる: g(5) + g(9) + Δ(9) = 1 + 2 + 0 = 3 > 2。併合しない。
3. 3を調べる: g(3) + g(5) + Δ(5) = 1 + 1 + 0 = 2 ≤ 2。3を5に併合し、(5,2,0)になる。
4. 2を調べる: g(2) + g(5) + Δ(5) = 1 + 2 + 0 = 3 > 2。併合しない。

結果は(1,1,0) (2,1,0) (5,2,0) (9,2,0)で、表のn = 6 の行と一致する。

n = 7 で値7を入れるときは、後続が(9,2,0)なので、Δ = 2 + 0 − 1 = 1 になり、(7,1,1)が入る。直前のタプル(5,2,0)の最小順位は 1 + 1 + 2 = 4 なので、値7の最小順位は 4 + 1 = 5、最大順位は 5 + 1 = 6 になる。整列した1、2、3、5、7、8、9のうち7は5番目なので、範囲[5, 6]に入っている。

n = 10 の最後の要約は(1,1,0) (5,4,0) (6,1,2) (10,4,0)で、10件が4個のタプルに縮む。タプル(6,1,2)の最小順位は 1 + 4 + 1 = 6、最大順位は 6 + 2 = 8 である。値6の真の順位は6だが、要約からは6〜8のどれかとしか分からない。条件2のg + Δ = 3 ≤ ⌊2 × 0.2 × 10⌋ = 4 を満たしている。

### 問い合わせの結果

上の最終状態(n = 10、ε = 0.2、許容幅 e = ε × n = 2)に問い合わせる。タプルの最大順位は、先頭から 1、5、8、10 である。値は1から10の異なる整数なので、値と真の順位は等しい。

| q | 目標順位r | r + e | 返される値 | 順位誤差 |
|---|---|---|---|---|
| 0 | 1 | 3 | 1 | 0 |
| 0.1 | 1 | 3 | 1 | 0 |
| 0.25 | 3 | 5 | 5 | 0.2 |
| 0.5 | 5 | 7 | 5 | 0 |
| 0.75 | 8 | 10 | 10 | 0.2 |
| 0.9 | 9 | 11 | 10 | 0.1 |
| 1 | 10 | 12 | 10 | 0 |

q = 0.25 では、目標順位3に対して r + e = 5 を探す。最大順位が5を超える最初のタプルは(6,1,2)(最大順位8)なので、1つ前の(5,4,0)の値5を返す。値5の順位は5で、目標順位3との差は2、件数10で割って0.2である。q = 0.75 は、最大順位が10を超えるタプルがないので、末尾の値10を返し、順位誤差は(10 − 8) ÷ 10 = 0.2 になる。

どの行も順位誤差は0.2以下で、ε = 0.2 を超えない。q = 0.25 と q = 0.75 では、ちょうどεに達している。保証は上限であり、境界でちょうど達する場合がありうる。

## 例 ε = 0.05、値 3、1、2(圧縮が働かない場合)

ε = 0.05 のとき、圧縮の周期は max(1, ⌊1/0.1⌋) = 10 件である。3件の間は圧縮が起きず、閾値 ⌊2 × 0.05 × 3⌋ = 0 でもあるので、すべてのタプルが(値, 1, 0)のまま、(1,1,0) (2,1,0) (3,1,0)になる。要約は全件を覚えているので、どの分位点でも厳密値(最近順位法)を返す。

## 費用と限界

- 挿入は、二分探索で場所を決めたあと、後ろのタプルを1つずつずらす。移動の数はタプルの数に比例するので、εが小さくてタプルが多いと遅くなる。
- 圧縮の周期ごとに、すべてのタプルを調べる。
- 簡略版の圧縮は、要約の大きさの上限を証明していない。論文のバンドを使う圧縮との違いは`overview.md`にまとめた。
- 保証されるのは、どの分位点でも順位誤差がε以下になることだけで、値の誤差(相対誤差)は保証しない。値が疎な裾では、順位が近くても値が大きく離れることがある。
