# DDSketch: 対数マッピングと相対誤差の保証

DDSketch は、値の大きさに対する**相対誤差**を保証する分位点の近似手法である。値を対数で等比のバケットに振り分け、各バケットの件数だけを覚える。この実装は `src/relative-error/` の `createDDSketch`(`ddsketch.ts`)と `createLogMapping`(`log-mapping.ts`)で、扱う値は有限の正の数である。

## 対数マッピング

相対誤差の許容値 α(0 < α < 1)から、バケットの幅を決める比 γ を次のように定める。

```
γ = (1 + α) / (1 − α)
```

番号 i のバケットは、区間 `(γ^(i−1), γ^i]` に入る値を数える。値 x の番号は `i = ⌈log_γ x⌉ = ⌈ln x / ln γ⌉` である。区間は下側を含まず、上側を含む。

実装は、対数で番号を推定したあと、写像自身が計算した境界 `γ^(i−1)` と `γ^i` と比べて補正し、`下側の境界 < x <= 上側の境界` が厳密に成り立つようにする。補正の比較は最大 3 回である。`γ^i` の累乗そのものの値でも、浮動小数点の丸めで隣の番号に入ることはない。

## 代表値と α の関係

バケットの推定値(代表値)は、区間の両端から見て相対誤差が等しくなる点にする。

```
代表値 = 2γ^i / (γ + 1)
```

区間の両端での相対誤差を確かめる。

- 上端 `x = γ^i`: `(γ^i − 2γ^i/(γ+1)) / γ^i = 1 − 2/(γ+1) = (γ−1)/(γ+1)`
- 下端 `x = γ^(i−1)`: `(2γ^i/(γ+1) − γ^(i−1)) / γ^(i−1) = 2γ/(γ+1) − 1 = (γ−1)/(γ+1)`

`γ = (1+α)/(1−α)` を代入すると `(γ−1)/(γ+1) = α` なので、**両端でちょうど α** になる。区間の内側では誤差は端より小さいので、バケット内のどの値でも相対誤差は α 以下である。

推定値は「目標順位の値が入ったバケットの代表値」である。目標順位は最近順位法(`⌈n·q⌉` 番目)で決めるので、縮約が起きない間は、最近順位法の厳密値に対する相対誤差が α 以下になる。

## 桁によらず保証が成り立つ理由

番号は `ln x / ln γ` の切り上げで決まる。x を 10 倍すると `ln x` は `ln 10` だけ増えるので、番号は `ln 10 / ln γ` だけ進む。つまり番号の**差**は値の比だけで決まり、値が 1 付近でも 100 万付近でも、バケットの幅は値に対して同じ割合になる。そのため、相対誤差の上限 α は桁によらない。

α = 0.01 では、10 倍ごとに番号が約 115.1 進む(値 1 の番号は 0、値 1,000 の番号は 346、値 1,000,000 の番号は 691 で、差は 346 と 345)。固定幅のヒストグラムでは、バケットの幅が小さい値には粗すぎ、大きい値には細かすぎるが、DDSketch では値の大きさに比例して幅が変わる。

## 数値例(α = 0.01)

α = 0.01 のとき、γ と ln γ は次のとおりである(有効数字 6 桁)。

| 項目 | 値 |
|------|----|
| γ | 1.0202 |
| ln γ | 0.0200007 |

値 100 と 100,000 の番号、境界、代表値を示す(境界と代表値は有効数字 6 桁、相対誤差は有効数字 3 桁)。

| 値 | 番号 | 下側の境界 | 上側の境界 | 代表値 | 相対誤差 |
|----|------|-----------|-----------|--------|---------|
| 100 | 231 | 99.4996 | 101.51 | 100.495 | 0.00495 |
| 100000 | 576 | 98753.6 | 100749 | 99741.2 | 0.00259 |

どちらの相対誤差も α = 0.01 以下である。値が 1,000 倍になっても、バケットの幅の割合(上側の境界 ÷ 下側の境界 = γ)は変わらない。

## バケット数の上限と縮約

保持するバケットの範囲(最小番号から最大番号まで)は、上限 m 以下にする。既定は 2048 である。上限を超える番号が来たら、**小さい番号の側**を縮約する。

- 上側に範囲を超える番号が来たとき: 範囲の長さがちょうど m になる最小番号 `t = i − m + 1` を決め、`t` より小さい番号の件数を、すべて `t` のバケットに合算する。
- 下側に範囲を超える番号が来たとき: 範囲の長さが m を超えない最小番号のバケットに、その値を数える。

どちらの場合も総件数は変わらない。縮約は小さい番号の側だけで起きるので、**最大番号のバケットは常に本来の値だけを数える**。縮約の回数と、合算先の番号の最大値が記録され、`inspect()` の `collapseCount` と `collapsedUpperBound`(合算先の番号の上側の境界。縮約がなければ `null`)で観察できる。

### 保証が残る分位点

合算先の番号を c とする。推定に使ったバケットの番号が c より大きければ、そのバケットは本来の値だけを数え、それより小さい番号の件数は合算先 c 以下に入っているので、目標順位の並びは保たれる。したがって**推定値が `collapsedUpperBound` より大きいとき、相対誤差は α 以下**である。`collapsedUpperBound` 以下の推定(主に低い分位点)には保証がない。

保証が残る範囲の目安は、m 個のバケットが覆う値の比 `γ^m` である。α = 0.01、m = 2048 では `γ^2048 ≈ 6.16e17` なので、最大値から約 6.16e17 分の 1 までの範囲に値が収まっていれば、縮約は起きない。α = 0.01 で m = 64 なら `γ^64 ≈ 3.60` で、最大値の約 3.6 分の 1 までの値しか保証されない。

## 非正規化数の範囲での注意

正の最小の正規化数 `2^−1022`(約 2.2e−308)より小さい値(非正規化数)では、浮動小数点の有効桁が減るため、相対誤差の上限が丸めの範囲で破れることがある。この実装は、`Number.MIN_VALUE` から `Number.MAX_VALUE` までの値を受け付け、境界と代表値は常に有限の正の数にする(代表値は正の最小値以上、正の最大値以下に収める)が、上限 α の保証は**正規化数の範囲**で確かめている。性質テストの入力も正規化数に限る。

## 費用

- 投入: 範囲内なら比較 5 回以下(写像の補正 3 回以下 + ストアの範囲判定 2 回以下)、移動 2 回(件数と総件数)。範囲の拡張や縮約を伴うときは、移動が `m + 1` 回以下。
- 問い合わせ: 先頭から累積件数を足してスロットを選ぶので、比較は保持バケット数以下。
- メモリ見積もり: `(保持範囲の長さ + 6) × 8` バイト。上限は `(m + 6) × 8` バイトで、件数には依存しない。
