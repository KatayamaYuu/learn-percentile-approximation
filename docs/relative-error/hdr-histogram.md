# HDR Histogram: 有効桁数ベースのバケット構造

HDR Histogram は、**有効桁数** d と追跡する値の範囲から、固定のバケット構造を作る分位点の近似手法である。DDSketch のように比で番号を決めるのではなく、2 倍ごとの区間を等しい幅の副バケットに分ける。この実装は `src/relative-error/` の `createHdrHistogram`(`hdr-histogram.ts`)と `createHdrLayout`(`hdr-layout.ts`)で、扱う値は L 以上 H 以下の有限の正の数である。

## 設定

| 記号 | 意味 | 条件 |
|------|------|------|
| L | 最小の識別単位(`lowest`) | 有限の正の数 |
| H | 追跡する最大値(`highest`) | 有限の正の数で 2L 以上、H ÷ L が有限 |
| d | 有効桁数(`significantDigits`) | 0 以上 5 以下の整数 |

L より小さい値と H より大きい値は、`unsupported-value` として拒否する(状態は変わらない)。

## 副バケット数 S

副バケット数 S は、`2 × 10^d` 以上の最小の 2 のべき乗である。

```
S = 2^⌈log2(2 × 10^d)⌉
```

| d | S |
|---|---|
| 0 | 2 |
| 1 | 32 |
| 2 | 256 |
| 3 | 2048 |
| 4 | 32768 |
| 5 | 262144 |

## 区間と副バケットの構造

値 x を L 単位の整数 `u = ⌊x / L⌋` に切り捨てる。

- **区間 0**: `u` が S 未満。幅 1 単位(L)のバケットが S 個並ぶ。番号は `u` そのもの。
- **区間 k(k ≥ 1)**: `u ∈ [S × 2^(k−1), S × 2^k)`。この範囲を、幅 `2^k` 単位の等しいバケット `S / 2` 個に分ける。番号は `S + (k−1) × S/2 + (⌊u / 2^k⌋ − S/2)`。

バケットの総数は、`⌊H / L⌋` を含む最小の区間番号を K として `S + K × S/2` である。総数は作成時に決まり、件数配列も作成時に確保する。総数が `2^22`(4,194,304)を超える設定は、防御のためエラーにする(`field` は `'significantDigits'`)。

推定値(代表値)は、バケット `[下側の境界, 上側の境界)` の**中点**である。

## 誤差の上限

バケットの幅の半分が誤差の最大なので、次の上限が成り立つ(浮動小数点の丸めの範囲で)。

- `x >= S/2 × L` のとき、相対誤差は `1 / S` 以下。区間 k のバケットの幅は `2^k × L`、その下端は `(S/2) × 2^k × L` 以上なので、中点との差は `2^(k−1) × L ≤ x / S` になる。区間 0 で `u ≥ S/2` の部分も、幅 `L` から同じ上限になる。
- `x < S/2 × L` のとき(L 単位の領域)、絶対誤差は `L / 2` 以下。バケットの幅が L で固定だからである。この領域では相対誤差は `1 / S` に収まらない(値が L に近いほど大きくなる)。

d = 2(S = 256)なら、`x >= 128 L` の値は相対誤差 1/256(約 0.39%)以下で、`x < 128 L` の値は絶対誤差 L/2 以下である。

## 元の HdrHistogram との違い

元の HdrHistogram(Java 実装など)は、分位点の問い合わせでバケットの**上端**(そのバケットで等価な最大値)を返す。この実装は**中点**を返す。上端を返すと誤差は最大でバケットの幅ぶん(中点の 2 倍)になり、相対誤差の上限が `2 / S` になる。中点を返すことで、上限を `1 / S` に半減している。元の実装と同じ出力は再現しない。

また、この実装は 0 以下の値と、H を超える値への範囲の自動拡張を扱わない。

## 数値例(L = 1、H = 3,600,000、d = 2)

| 項目 | 値 |
|------|----|
| S | 256 |
| バケットの総数 | 2048 |

総数は `256 + 14 × 128 = 2048` である(`⌊H / L⌋ = 3,600,000` を含む区間は `256 × 2^13 = 2,097,152` 以上 `256 × 2^14 = 4,194,304` 未満で、区間番号 K = 14)。

値の番号、境界、代表値を示す。

| 値 | 番号 | 下側の境界 | 上側の境界 | 代表値 |
|----|------|-----------|-----------|--------|
| 1 | 1 | 1 | 2 | 1.5 |
| 100 | 100 | 100 | 101 | 100.5 |
| 150 | 150 | 150 | 151 | 150.5 |
| 1000000 | 1780 | 999424 | 1003520 | 1001472 |

値 1、100、150 は `u < S`(= 256)の区間 0 に入り、幅 1 のバケットで、代表値との差は 0.5(= L / 2)である。値 100 は `S/2 × L = 128` 未満なので、相対誤差は 0.5% で `1/S` を超えうるが、絶対誤差は L/2 以下に収まる。値 1,000,000 は区間 12 に入り、バケットの幅は `2^12 = 4096`、代表値との差は 1,472 で、相対誤差は約 0.15% と `1/256` 以下である。

有効桁数ごとの S とバケットの総数、メモリ見積もり(L = 1、H = 3,600,000)は次のとおりである。

| d | S | 総数 | メモリ見積もり(バイト) |
|---|---|------|------------------------|
| 0 | 2 | 23 | 216 |
| 1 | 32 | 304 | 2464 |
| 2 | 256 | 2048 | 16416 |
| 3 | 2048 | 13312 | 106528 |
| 4 | 32768 | 147456 | 1179680 |
| 5 | 262144 | 786432 | 6291488 |

メモリ見積もりは `(3 + 総数 + 1) × 8` バイト(数値 3 個 = L、H、d と、バケットの件数 + 総件数のカウンタ)で、件数に依存しない。

## 費用

- 投入: 比較 4 回以下(区間 0 かどうかの判定と、区間番号の推定の補正)、移動 2 回(件数と総件数)。
- 問い合わせ: 比較はバケットの総数以下。
- メモリ見積もり: 作成時から変わらない。
